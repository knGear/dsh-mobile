部署方式对比

Termux 原生proot Ubuntu
核心dsh 跑在 Termux Android 用户态dsh 跑在 proot 模拟的 Linux
性能原生 ARM64, 无翻译层, 最快 ✓proot syscall 翻译, 约 10-30% 损耗(I/O 尤慢)
权限Android 应用沙箱 + termux-am/storage/RUN_COMMANDLinux 完整权限模型(可选 fake-root), 底层仍受 Android 沙箱 ✓
稳定直接进程, Android 12+ 需 setsid 守护(已解决)proot 偶有边界 case; 环境标准 apt 包全 ✓
安全Android 沙箱隔离, termux.properties 可调双层隔离(沙箱+Linux 权限) ✓
兼容原生模块(node-pty/koffi/sharp)需 Termux 编译, 有坑标准 Linux, npm 原生模块预编译/易编译, 少坑 ✓
部署难度中: 一键脚本但需多项修补易: proot 内 apt 装齐依赖, npm 直装, 无修补 ✓
维护升级需重打修补: npm 卸载重装后 wrapper/补丁丢失npm 升级即可, 修补少 ✓

两者都装 dsh; 区别仅 dsh 跑在哪一层。性能优先选 Termux 原生; 兼容/依赖完整优先 proot Ubuntu。✓ = 该项更优。
